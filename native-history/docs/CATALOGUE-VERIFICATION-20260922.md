# 历史集表验证恢复

历史续播可以先播放已保存的单集，再恢复集表。此前目录搜索/读取抛出的 `SourceVerificationRequired` 被普通错误分支吞掉，媒体可播时用户只看到“重试集表”，无法从这里完成目录验证。

现单独保留目录挑战及原始 method/body，提供显式“验证并恢复集表”。验证页不会自动打开；打开后暂停视频，并保留原播放器、进度和播放意图。取消或成功后返回原播放器，成功只重试目录，不重新解析当前媒体。换源、换集和会话销毁使旧挑战失效，取消后的异步结果不能重新打开旧页面。

验证期间发生实际后台停止或睡眠到期，返回后保持暂停；普通取消则恢复进入验证前的播放意图。睡眠到期原有“定时停止”菜单保留，不因验证结束而清除。

本轮同时复现并修复通用播放器返回键问题：在 DOWN 上关闭菜单会移除原焦点节点，使 UP 可能再次落到返回分发器而退出暂停播放器。现 DOWN 只记录，匹配且未取消的 UP 才执行一次；取消、重复和后台清理均不重复执行，没有用时间去抖代替按键配对。

## 验证与边界

本地候选 SHA256 `704287653848244495d306b18de6b39e9642f3cb8dd382afe65ef2c78adc4fce`，204 项单测、release lint 通过。`catalogue-verification` 使用隔离设置、独立睡眠定时器、本地视频及明确的合成验证值；不识别真实验证码、不改用户资料或来源。

现代模拟器 `catalogue-verification-modern-6.txt` 通过：显式入口、物理返回保留原 engine/暂停进度、原 POST 与 Cookie 恢复目录、媒体解析只调用一次、睡眠到期不自动续播、实际 HOME 收到 ON_STOP 后返回不自动播放，以及旧会话验证页销毁。现代原 `player-controls` 回归也通过。

旧电视早期失败分开保留：截图证明控件存在但 `rootInActiveWindow` 为空，测试改用当前应用的活动/焦点窗口，结束时恢复无障碍标志；应用内注入 HOME 没有触发 PAUSE/STOP，改用既有测试的系统 HOME 输入；恢复前台必须等原 Activity RESUMED，避免读取旧窗口节点后过早注入按键。不能把测试观测修正称为生产功能修复。
