# Android TV 界面验收

先读项目设备/安装 runbook 和本次授权。设备地址、允许包名、型号必须来自当前任务，历史记录不能替代授权。每条 ADB 命令明确 `-s`；先核对 model/device、Android/ABI、包名/版本/证书。已有正式包与 preview 同名时不可用卸载、清数据、降级解决；需要并存就用独立 applicationId，并检查合并 manifest 的 authority、权限名、sharedUserId 和 deep link。记录构建 SHA、参数、APK hash 与真实安装身份。

## 观察顺序

1. 先找现有低清工具和经验。优先限时 H.264 连续采集、按需解码最新帧，减少高清截图开销；用 [现有工具适配脚本](scripts/observe.py) 复用项目外已有 `capture.py`/`latest_frame.py`，不复制一套采集引擎。工具位置和已验证差异见 [运行记录](references/observations.md)。
2. 连续编码流、按需取帧、定时 screencap 是不同方式。模型只看实际送入的帧，不能声称连续观看视频。记录采集是否仍运行、帧时间和内容变化；静态场景重复解码同一帧不等于实时更新。
3. 用 `uiautomator dump` 获取 text/content-desc、bounds、focused，和图像一起判断按钮与焦点。Flutter semantics 可能缺少节点、焦点或滚动子树；空树不能推断无控件。先用真实遥控键促发状态，再读树/图；不默认开启系统无障碍或改变 ADB 安全设置。
4. 小字、裁剪、滑条数值或异常边界使用原始高清 screencap。工具没有返回有效帧就报告限制，可降级到限时 scrcpy 录制后抽帧，再降级到按需截图；不能把降级截图称为实时流。不要为了观测启动无界录制。

## 行为验收

从已知焦点出发，方向键、OK、Back 每组操作后核对可见状态及树。验证分类重复点击、嵌套页返回、弹窗取消/确认、输入框键盘退出、滑条方向键变化及返回后的焦点。坐标点击是可用补充，但报告中区分混合输入和纯遥控。

播放恢复必须记录具体触发点：加载中取消应看到取消提示；已经播放后的迟到点击不计为取消通过。换源取消前后比较暂停状态/位置/焦点，再验证下一请求可成功；手工选集从头播放不能当作精确续播。MediaSession 是佐证，不是独立原生时钟或音画同步证明。站点挑战不绕过，网络失败、取消、原生超时分别记结果。

## 证据与清理

保存关键帧、对应 XML、操作序列、时间、精确包身份、必要的过滤日志。原始系统日志可能含地址、账号或内容，不自动公开；外部同步只在授权范围内写结果和未测范围。

启动媒体前记录音量/静音，以低音量或静音验收；结束通过 Back/正常 UI 停播、停止本任务采集，核实 recorder/宿主子进程退出，再恢复临时音量及 UI 配置。不要杀其他任务的 adb server/录制进程。按当前要求恢复休眠状态；不默认重启、冻结桌面或改默认 HOME。保留安装与数据，不用清空掩盖失败。

技能不会授权设备操作、安装、外部发布或桌面改动。报告通过、失败、未测与观测工具限制，链接真实证据；不会因工具可启动就标记业务通过。
