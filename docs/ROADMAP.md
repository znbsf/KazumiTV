# 后续计划

目标仍是迁移表中适用于Android TV的基本全部模块，不以本次公开测试版替代完整迁移。

## 首要原则：播放是关键功能

2026-09-16 用户明确要求：后续以播放为重点。播放可靠性优先于非必要 UI 润色和新增外围功能；整体迁移目标保留，但先解决阻断实际观看的问题。

2026-09-22 验收范围调整：用户明确取消整集播放测试。当前通过短时真实播放与各项操作/恢复专项验证完整操作路径，不再等待自然播完一集，也不将历史整集证据移作新版验收。未测的稳定性与设备边界继续如实记录。

2026-09-23 发布节奏调整：用户指出Preview发布过于频繁。以Preview6作为当前公开测试基线；日常修复先累积为内部候选，不为每次修复或专项测试单独发Release。完成一个明确阶段的功能与相关回归后再集中发布，说明相对上一公开版的实际变化、验收范围和剩余问题；阶段内继续提交代码、维护证据和保留用户数据。

- 先完整对照并复用上游规则、通用解析和验证流程，再适配电视与播放引擎差异；只有证据证明通用能力不足时，才增加站点专用逻辑。不能把迁移遗漏当作源不可用，也不能默认逐个源重写。
- 验收覆盖真实来源搜索、验证、选线选集、进入播放器、持续播放、快进暂停、换源换集、返回续播，以及失败重试、签名过期、网络和待机恢复。优先补齐尚未通过的路径。
- 以真机真实来源的完整观看路径为依据，逐条记录来源、线路、集数、设备、结果与限制；构建通过、受控测试或单次首帧都不能代表播放已完成。
- 分开记录客户端缺陷、上游规则问题、来源失效和设备兼容限制；明确修复与未解决范围，避免“能播放”或“全部完成”的笼统结论。

1. 优先补真实观看闭环：来源兼容、验证码、签名过期重解析、连续换集、历史返回和进程重建；修复外播自动返回。
2. 补业务完整性：搜索过滤、资料与评论、规则编辑/诊断、日志脱敏、统计与屏蔽管理。
3. 完成数据与离线：真实WebDAV和冲突选择、历史/Bangumi同步、下载轨道与离线资料、空间故障和任务恢复。
4. 逐项推进增强：Syncplay、PiP、外播协议、投放/截图；Anime4K、帧率、HDR和音频必须有目标设备效果及成本证据。
5. 稳定版门槛：多个设备/系统版本、长时播放与内存/热稳定、发布签名和升级、完整许可清单与CI。未通过的项目保留在功能台账，不用“能启动”代替验收。
