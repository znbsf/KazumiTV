# 弹弹play接入与发布门槛

2026-10-10 实机诊断：正式身份 0.4.1 候选的自动匹配 `/api/v2/bangumi/bgmtv/{id}` 和手动搜索 `/api/v2/search/episodes` 均返回 HTTP 403。该构建没有注入 `DANDANAPI_APPID` 和 `DANDANAPI_KEY`，而 `String.fromEnvironment` 未提供默认值，所以应用认证配置为空。这是已确认的构建配置缺口；不能把此次失败只归为临时网络故障。

当前签名实现使用秒级时间戳、URI path 和 `base64(sha256(AppId + Timestamp + Path + AppSecret))`，与[官方接入说明](https://doc.dandanplay.com/open/)一致。公开读取接口也要求应用认证；不需要为了搜索和读取弹幕新增用户登录。搜索的 `v2=true` 和评论的 `withRelated=true` 均符合[官方变更记录](https://doc.dandanplay.com/open/changelog.html)。不要通过修改 User-Agent、移除认证、借用他人密钥或关闭安全校验规避拒绝。

10月2日旧实验版的实机日志已经记录同类 bangumi/bgmtv 端点 403，10月4日恢复测试也有相同现象。旧实验版、公开0.4.0、main 93e316d8 和候选94ade172都使用相同的编译期配置入口。因此没有证据表明本次弹幕请求生命周期修复引入了403；历史日志没有服务端错误头，不能进一步断言每一次历史403都由同一原因造成。

## 合法接入的最小操作

维护者先确认是否已有获服务方授权、适用于本项目的应用；若没有，需自行在[开发者中心](https://dev.dandanplay.com/)完成注册、资料和邮箱验证、应用审核。不要把 AppSecret 发到聊天、提交到仓库或附进 Release。此次诊断没有查找或读取私有凭据，也没有代建账号或密钥。

获得授权后，在本机受控构建流程中通过 `--dart-define-from-file=<仓库外受保护JSON文件>` 注入 `DANDANAPI_APPID` 与 `DANDANAPI_KEY`。只记录配置是否存在，不打印值；配置文件及构建中间件不得进入源码包或公开附件。构建时注入不能保证客户端二进制无法提取密钥，分发方式须遵守服务方授权条件。现有免密钥 PR/候选 CI 保持隔离，不能据其成功宣称真实弹幕服务通过。

重新构建后，必须重新记录精确源码、APK哈希、签名和版本，并在实机验证自动匹配、手动搜索、真实弹幕显示/同步、切集和取消迟到响应。已有94ade172 APK与验收记录应保留，不能拿新APK覆盖旧回执。

若已正确注入仍403，只采集 HTTP状态及官方 `X-Error-Message` 的已知分类（Missing Authentication Headers、Invalid Timestamp、Invalid AppId、Invalid Signature、Invalid AppSecret）；不要输出原始请求头、响应体或签名。现有日志未采集该头，因此本次没有声称获得服务端精确拒绝分类。再按分类核对设备时钟、应用状态和签名，必要时由维护者联系服务方。
