# KazumiTV 0.4.8 发布说明草稿

[Release 列表中的 0.4.8 草稿](https://github.com/znbsf/KazumiTV/releases)及 11 项正式附件已备齐，尚未公开（release ID 445889609）。当前公开稳定版仍为 0.4.7。

## 本版变化

- 修复完整 MP4 缓存续播、前后拖动及再次播放时可能黑屏的问题。已保存文件可独立响应播放器的并发读取，未完成缓存继续保留写入约束。
- 缓存播放失败时，可选择“关闭视频缓存并重试”，保留进度并重新解析原来源；离线入口提供“关闭视频缓存并返回”。关闭开关不会删除已有缓存文件。
- 弹幕服务超时与 429 限流分别提示，可选择“关闭弹幕并默认关闭”。关闭后停止当前弹幕和后续自动请求，手动成功选取弹幕可恢复开启。
- 沿用有效弹幕、搜索及剧集列表 6 小时内优先使用缓存的策略，涵盖两小时内的重复播放；缓存不能消除所有服务端额度限制。
- 存储打开失败时保留原文件并提示错误；改善 WebDAV 写入失败保全和收藏设备隔离、下载剧集身份及排队弹幕缓存、HLS 不确定分段保留、规则仓库配置与验证 Cookie 范围、DLNA 传输和媒体标题兼容。

## 验证范围

缓存并发读取有 31 项定向回归，播放恢复、失败按钮和弹幕缓存后续 6 文件 88 项相关检查通过；静态检查无 error/warning。此前上游修复合入前完成 1733 项 Flutter 与 29 项网页测试，具体版本及合成输入边界见[项目状态](PROJECT-STATUS.md)。

固定构建源码 `60e7c8a9` 的 [CI 43690043662](https://github.com/znbsf/KazumiTV/actions/runs/43690043662) 已 completed/success，检查与三个 ABI 构建均成功；CI 附件是独立 QA 包，正式签名附件由本机相同源码另行构建校验。后续交付文档不冒充 APK 源码或该 CI 的受测提交。

MiTV-ASTP0 / Android 9 / ARMv7 已验证正式身份修复候选的缓存续播、前后拖动及退出后二次播放。随后在同一电视的隔离 debug QA 包中，使用生产页面、控制器和原生解码器配本机合成坏 MP4、HTTP429 和实际接收超时，验证关闭缓存重试/返回、429 取消/关闭、超时提示/关闭、应用进程重启后开关持久化。弹幕关闭后再次播放自动请求为 0，未向真实弹幕服务制造限流。

两小时缓存边界使用自动测试，未在电视实际等待两小时；进程重启不代表电视重启。上述通过不外推所有媒体格式、HLS 实机、长播声画同步、真实 WebDAV 服务端或 DLNA 接收端。ARM64/x86_64 完成正式产物校验，尚无本版设备验收。

正式 ARMv7 0.4.8 / 208011 已在同一电视从修复候选 207251 同包同证书覆盖升级，安装后回读 APK 哈希一致；UID、首次安装时间和数据目录不变，最近观看样本、原作品“在看”收藏状态和深色主题可见。此轮使用静态截图与最新控件树、ADB 及一次补充坐标点击核对启动和可见数据，没有再次播放或全数据库逐条比对。既有播放和故障验收保持原范围，未冒充全部在正式 0.4.8 包重测。
